# 设计

总约束见根目录 `AGENTS.md`。这个目录记录方向、已经定下来的决定和还没定的事。

「已定」一节是用户确认过的；其余各节写的是方向和建议，实现到那一步时先和用户确认细节，不要当成既定事实照着做。已经实现的部分见「实现进度」，实现时定下的细节见各模块的文件（见「文件索引」）。

本文件只讲总体设计：目标、已定的事、要做与不做的功能、实现进度。各模块的设计、实现时定下的细节、实测记录与查证过的外部事实分在同一目录的文件里，见文末的「文件索引」。

## 目标

- 管理员在聊天里生成邀请链接，经链接添加机器人的用户可以和大模型对话。
- 对用户无感：QQ 与机器人的单聊只有一个会话，不让用户用 `/new`、`/list` 这类命令管理 session，分段与回溯由机器人自己完成。
- 能在 2 核 2G 的机器上跑起来。

要支持的能力，由简到繁：

1. 用户提问，大模型回答。
2. 按消息的性质选模型：先做一次分类，再交给对应类别的模型（例如解决问题用一个，情感支持用另一个）。类别与模型的对应关系是配置出来的列表。
3. 语音输入：模型支持音频就原样给，不支持就先转成文字。
4. 多个输入对应一次提问：一条消息里同时有图片和文字；先发图片或文件，再用文字或语音提问。
5. 话题回溯：聊过 A，又聊了 B、C，再回到 A 时能带上 A 的上下文，同时知道 B、C 的存在。
6. 提醒事项：「提醒我 / 告诉我 / 帮我……」，到点由机器人主动发出。
7. 联网搜索：直接用服务商内置的搜索工具，本项目不自己实现搜索。
8. 展示处理过程：模型思考、搜索时让用户看到进展，类似 ChatGPT 的思考摘要。

## 已定

| 事项 | 决定 |
| --- | --- |
| QQ 侧 | 只经由 pyqbot |
| 部署 | docker compose：机器人本体加其它服务。pyqbot 开发与部署都从 GitHub 安装，固定到某个 commit；pyqbot 改了要用时，推到 GitHub 后在本仓库升级固定的 commit（用户 2026-11-20 决定，取代 11-19 的「开发时用本机 `../pyqbot` 的可编辑安装」） |
| 密钥 | 环境变量，由 `.env` 经 compose 的 `environment:` 逐项注入，每个服务只拿自己需要的 |
| 静态设置 | TOML 配置文件：模型列表、决策提示、各种时长与配额 |
| 运行时会变的数据 | 数据库：授权名单、邀请令牌、对话与记忆 |
| 大模型调用 | 官方 SDK：`openai`、`google-genai`（这两个依赖已获同意）；每个模型可以配置推理强度 |
| 代理与端点 | 模型侧按服务商配置接口地址与代理（http、https、socks5、socks5h），为此加了依赖 `socksio`；QQ 侧同样可以配接口地址与代理（`[qq]`，代理经 `pyqbot.Bot(proxy=...)`，作用于接口、网关与附件下载） |
| 选模型 | Decisions API；OpenAI 与 Gemini 两家都适配，配置里固定选一家 |
| 记忆 | 自己做「话题线加一次决策调用」，见[「记忆」](memory.md)；暂时不引入 Hindsight、mem0 这类外部记忆服务 |
| 联网搜索 | 只用服务商内置的搜索工具，OpenAI 与 Gemini 都打开（用户 2026-11-19 决定，提前到里程碑 6 之前做）。两家的展示条款由用户另行确认，见[「查证过的外部事实」的「内置搜索」](external-facts.md#内置搜索) |
| 表情 | 一律忽略：表情标记从文字里去掉，只由表情组成的消息只记进流水，不进模型的输入、不影响轮次（用户 2026-11-19 决定） |
| 处理过程的展示 | 过程一条消息，回答另起一条；过程消息回答之后留着，不撤回（用户 2026-11-19 决定：QQ 的流式消息撤回不了）。过程消息用纯文本发、每步一行，搜索写成进度式的一行（用户 2026-11-19 QQ 实测后决定）。见[「展示处理过程」](search-and-process.md#展示处理过程) |
| 生成图片 | 对话模型调用我们自己声明的画图函数，由程序调用可配置的图片模型出图，两家都适配；不用 OpenAI 内置的 `image_generation` 工具。配置是 `[image_generation]` 表与 `[[models]].image_generation` 开关（用户 2026-11-19 决定），细节见[里程碑 10](image-generation.md) |

同一个值只有一个来源：密钥不进配置文件，配置文件里的设置不再从环境变量覆盖。

暂时不用外部记忆服务的理由：调研到的记忆库存的都是提炼出的事实，没有一个会自动给连续对话分段；服务商自带的会话状态只是一条线性历史；Hindsight 的部署对 2G 的机器太重。以后引入的可能性很低，但不排除。

### 已定要做的功能

除上面八项能力外，这些也从一开始就做，细节实现时再定：

1. **邀请带备注**：创建邀请时填一个备注，兑换后成为该用户的名字，管理、用量、日志都用它。机器人看不到 QQ 号，昵称会改也会重名。
2. **管理员的管理面**：列出和停用用户、撤销邀请、查看用量、临时停机。用斜杠命令直接解析，不经过大模型；可以用 pyqbot 的按钮与自定义菜单做成点按。
3. **用量记账**：从第一条消息开始，每次调用记下用户、模型和 token。配额、限流、成本归因都靠它。
4. **遗忘与查看记忆**：「忘掉这件事」「你都记得我什么」做成模型的工具，用户照常说话即可。
5. **欢迎语与拒绝语**：授权成功时说明能做什么、聊天内容会发给第三方模型、提醒功能需要保持「允许主动发送」。未授权的人只回一次固定的拒绝，不调用大模型。
6. **出错时的表现与备用模型**：调用失败或超时时给用户一句明确的话，不沉默；每个类别可以配一个另一家服务商的备用模型。
7. **数据库的迁移与备份**：表结构从第一版就带版本号和迁移机制，并定时备份。
8. **不支持的消息的兜底**：转发的聊天记录、视频、卡片等先明确回一句「暂不支持」。表情包要单独处理，不能每张都触发看图和回复。
9. **「正在输入」**：模型还没开始输出时发，开始流式输出后就不需要了。pyqbot 已有 `send_typing()`。每次只请求几秒，有进展时再请求，像真人一样输一会、停一会（细节见 [7b](search-and-process.md#里程碑-7b-定下的细节)）。
10. **给管理员的告警**：机器人掉线、额度用尽等，直接发到管理员的 QQ。

### 不做

| 事项 | 态度 |
| --- | --- |
| 群聊 | 明确不做 |
| 自己实现搜索 | 明确不做，只用服务商内置的工具 |
| 主动关怀 | 暂时不做 |
| 到点执行一个请求 | 已定要做，但以后再做；提醒表先留好字段，见[「提醒事项」](reminders.md) |
| 给管理员的每日摘要 | 暂时不做，优先级低 |
| 语音形式的回复 | 暂时不做，但要留好口子，见[「留给以后的口子」](memory.md#留给以后的口子)；图片形式的回复改为要做，见[里程碑 10](image-generation.md) |

## 使用约定

- 动手前先读本文件，再读要动的那部分对应的文件。
- 新的决定写进对应的文件；影响整体方向的（新的「已定」、要做或不做的功能、里程碑的状态）同时更新本文件里相应的表。
- 没有标「已定」、也没有写明是用户决定的内容是方向和建议，实现到那一步时先和用户确认，不要当成既定事实照着做。
- 同一段内容只写在一处，别处用相对链接指过去；新增文件时在「文件索引」里加一行。
- 实测前按 `AGENTS.md` 先取得用户同意。QQ 端到端与跨模块的实测记进 `live-tests.md`，只涉及一个模块的记在那个模块的文件里。
