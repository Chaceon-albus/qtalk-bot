# 接入与授权

谁能用机器人（里程碑 2）：邀请链接与邀请码、授权名单、管理员命令、欢迎语与拒绝语，以及重复推送与回复失败的处理。

pyqbot 已有的能力（实测结论见 pyqbot 的 `docs/errata.md`）：

- `generate_share_link(callback_data=...)` 生成邀请链接，`callback_data` 最长 32 个字符。
- 用户经链接添加后，`FRIEND_ADD` 的 `scene_param` 就是 `callback_data`。这时 `scene` 实测是 1000，不是官方文档写的 2003 / 2004，所以只认 `scene_param`。

链接不是门禁：用户还能通过搜索、群、资料页添加机器人。授权是机器人自己存的一张名单，默认拒绝，对应 `AGENTS.md` 的第一条不变量。管理员用环境变量 `ADMIN_OPENID` 标识，机器人看不到 QQ 号。

## 启动与模块

启动：`uv run --env-file .env python -m qtalk_bot`。配置有误时退出码是 2，数据库有误或连不上平台时是 1，都只打印原因。

| 模块 | 职责 |
| --- | --- |
| `access.py` | 数据层：用户、邀请、拒绝记录、服务状态与已处理事件的读写；同步函数，在调用方的事务里执行 |
| `commands.py` | 管理员命令的解析与执行 |
| `gate.py` | 授权核心，不依赖 pyqbot：输入普通数据，输出「回复什么」或「交给对话处理器」 |
| `chat.py` | 对话处理器的协议 `ChatHandler`；实现是 `bot.QQChat`，经 `batching.Batcher` 交给 `conversation.Conversation` |
| `texts.py` | 所有面向用户的固定文案 |
| `bot.py` | 接线层：把 pyqbot 的事件转给 `gate`，再按结果回复或交给对话处理器 |
| `__main__.py` | 启动入口 |

## 邀请

- `callback_data` 用随机的邀请码，在本地记录有效期与可用次数，默认一次性。链接可以被转发。
- 邀请码是 32 个十六进制字符，创建时必须带备注（最多 30 个字），兑换后备注成为用户的名字。
- 默认值在 `[invites]`：`ttl_hours`（默认 168，最大 87600）、`max_uses`（默认 1，最大 32）。
- 两条兑换途径共用同一个邀请码：经链接添加机器人（只认 `FRIEND_ADD` 的 `scene_param`），或在单聊里把邀请码发给机器人（兜底通道）。兑换是一个原子操作，是否过期在事务里判断。
- 在单聊里兑换时，未授权用户的消息里只要恰好包含一个邀请码（32 位十六进制，前后不紧挨字母数字）就算，这样对方把整段邀请原样发回来也能兑换；包含两个以上不同的码时不兑换。已授权用户和管理员的消息不受这条影响。
- 创建邀请时发两条：给管理员的一行状态（编号、备注、有效期、可用次数），和一条可以直接转发给对方的纯文本邀请，开头是「邀请您来和{机器人名}聊聊天！」，下面是链接与邀请码。机器人名在启动时经 `get_me()` 取得，取不到时写「这个机器人」。链接没能生成或被平台拒绝时，邀请里只留邀请码。

## 谁能用

- 管理员只看 `ADMIN_OPENID`。他在用户表里也有一行，方便流水和用量按用户编号记；没有邀请记录、又不是现任管理员的行没有权限，所以更换管理员后旧账号不会保留权限。
- 陌生人只回一次拒绝语，持久化记录，重启后也不重复。
- 发来已失效（过期、撤销、次数用完）的邀请码时每次都回「邀请码已失效」，不占用那一次拒绝。
- 被停用的用户只回一次说明；重新启用后再停用可以再回一次。
- 暂停只影响已授权用户的对话：他们的消息每条都回「暂停中」。陌生人、已停用的人仍按各自的规则处理，兑换邀请不受影响，管理员不受影响。
- 欢迎语里有「聊天内容会发给第三方大模型」的告知。只有确认欢迎语发出后才记下「已告知」；没告知过的用户发来消息时先回欢迎语，这条消息不交给对话处理器。

## 管理员命令

`/invite <备注>`、`/invites`、`/revoke <编号>`、`/users`、`/disable <编号>`、`/enable <编号>`、`/pause`、`/resume`、`/usage [编号]`、`/help`。只对管理员生效，直接解析，不经过大模型。`/help` 与几个列表用 Markdown 发送，备注和名字经 `texts.escape_markdown()` 转义（圆括号、方括号换成全角，其余特殊字符加反斜杠，换行换成空格）；平台明确拒绝时改发纯文本。单句的提示仍是纯文本。

- `/users` 每个用户一行：编号、名字、状态（正常、已停用、管理员、无权限）、加入时间，末尾是附件目录名（见[「存放与用户目录」](attachments.md#存放与用户目录)）。
- `/disable`、`/enable` 同时暂停与恢复这个用户的提醒，规则见[「提醒事项」](reminders.md)。

### `/usage`

- 统计「本月」（按配置的时区，本月 1 日 0 点起）与「累计」，不显示今天；不显示美元金额：那要维护一份价格表，暂不做。
- 不带参数：每个用户一项，列本月与累计的概要（输入 token 及其中缓存、输出 token、联网搜索次数、出图张数，为 0 的不显示），最后一项是所有人的合计；概要的 token 包括出图的。
- `/usage 编号`：这个用户的明细，分本月与累计两段，每段按用途分行（对话、决策、附件描述与摘要、话题摘要、出图；为 0 的用途不显示）；编号不存在、写法不对、没有用量时各回一句说明。单个用户的查询按 `user_id` 走用量表的索引。
- token 数小于 1000 原样写，之后用 k、M：整数部分一位时保留两位小数，两位及以上时一位，去掉末尾的 0（`texts.format_tokens()`）。
- 缓存数只算报告了输入 token 的那些调用的（缓存数永远是已报告输入的一部分）。一段时间里的调用都没有用量数据时写「N 次调用，都没有用量数据」；报告了、但都是 0 时写「报告的 token 都是 0」。
- Markdown 版最多两级列表，第二级每行以「本月：」「累计：」或用途名开头，嵌套被压平也看得懂；纯文本版不缩进，用空行分段。QQ 上的显示效果还没实测。

## 重复推送与回复失败

- 每条消息按消息 ID、每次加好友按事件 ID 记进 `processed_events`，与这次处理的全部数据库改动在同一个事务里提交；记过的直接丢弃。记录保留 7 天。
- 代价是「至多一次」：事务提交后、回复发出前进程退出，这次回复就丢了，但不会重复。
- 只有平台明确拒绝时（`bot.is_rejection()`：pyqbot 异常的 `outcome_unknown` 为假）才改发备用文案，并撤销「只回一次」的占位；不确定是否送达时两样都不做。`outcome_unknown` 为真的是请求发出后的网络错误、HTTP 5xx（不论有没有错误码）、没有错误码的 2xx/3xx 异常响应、`AuditPendingError`（已受理、等待审核）与 `PartialFailureError`（部分已生效）；为假的是带错误码的 2xx/3xx/4xx、HTTP 4xx、建连阶段的错误、取 access_token 失败。不按「带错误码就算拒绝」判断：5xx 带错误码也算说不准。所有用到「确定没发出 / 说不准」的地方（这里的备用文案与占位、对话的改发纯文本与停读、固定说明的送达状态）都经同一个判据（`bot._send_error()` 把它转成 `SendRejectedError` / `SendUncertainError`）。

## 对话处理器与日志

对话处理器：`ChatHandler.handle(user, message)`，`message` 是 pyqbot 的原始消息。放行决定与真正开始处理之间有一个很小的窗口，所以实现者必须在开始有代价的操作之前，在自己的事务里调用 `access.chat_allowed()` 再确认一次。

日志：不记 openid 与消息正文，提到用户时用编号和名字。`httpx2`、`httpcore2` 的日志压到 WARNING，因为 `httpx2` 在 INFO 级别会记下带 openid 的请求地址；两家大模型 SDK（`openai`、`google_genai`、`google.genai`）的日志也压到 WARNING，因为它们的 DEBUG 日志里有请求体（聊天内容）。
