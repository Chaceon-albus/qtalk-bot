# 展示与交互

回答怎样排版，哪些地方用按钮与指令面板，图片能不能随回答一起发出。过程消息与「正在输入」见 [search-and-process.md](search-and-process.md)，确认按钮现有的机制见[「记忆」里里程碑 6b 的实现](memory.md#里程碑-6b-的实现2026-11-20)。

起因（2026-11-20）：用户喜欢 ChatGPT 的 Intelligent UI 那种富展示（模型从一套固定的原生组件里挑，客户端边生成边渲染；OpenAI 没有公开接口），想知道本项目能向它靠拢多少。结论是能靠拢的主要是 Markdown 本身，交互只有按钮一种，凡是「点一下、原地变化」的（表单、计算器、标签页、小游戏）都做不了。

## QQ 侧能做到什么

出处是 pyqbot 的 `docs/guide.md`、`docs/errata.md` 与官方文档快照（`docs/upstream/qqbot-api-v2/`），以固定的那个 commit 为准。

- **Markdown**：官方「Markdown 消息」列的标题、文字样式（粗体、斜体、删除线）、链接、图片、有序与无序列表（可以嵌套）、块引用、分割线都能用；文档没列的代码块、表格（含对齐）、LaTeX、任务列表、脚注实测也能用，流式与普通消息的最终渲染一致（errata「Markdown：实际支持的语法比文档多」）。HTML 标签不生效，没有折叠。嵌套列表的子项要缩进 4 个空格，列表前面是普通文字时要先空一行（官方文档的「列表嵌套」）。
- **图片可以写在 Markdown 正文中间**：`![文字 #宽px #高px](地址)`，地址要能在公网访问，平台自己下载转存。实测过三种：单聊的流式消息正文中间放一张（地址在 QQ 自己的 CDN 上）、群消息里放第三方图床的图、素材库上传后引用。素材库每个机器人最多 100 张，连续 90 天没被引用就失效。
- **按钮只能随普通的 Markdown 消息发**，流式消息的请求体里没有键盘字段。三种按钮：回调（点了推一个互动事件）、指令（把一段文字填进输入框，`enter` 时直接以用户的身份发出，只有单聊）、跳转（https 链接）。回调按钮可以分组（同组点了一个，其余变灰）、带二次确认弹窗、选样式（线框、蓝底、红字）。
- **消息发出后不能修改**：单聊只有发送、流式发送、撤回三个接口。普通消息发出 2 分钟内可以撤回（聊天里留一条撤回提示），流式消息撤回不了。所以按钮发出后去不掉，「用过就消失」至多做到失效或变灰，见下面的[「按钮用过之后」](#按钮用过之后)。
- 点了回调按钮后的 `visited_label` 只是临时显示，收到下一条消息后按钮又显示回原来的文字（errata「回应互动」）。
- **指令面板**（输入 `/` 时弹出）可以只关联指定的用户（errata「指令面板」实测的就是只关联一个用户的单聊面板）；**底部的自定义菜单**对所有用户相同。

## 已定

### 格式说明只列能力

系统提示词里的格式说明（`prompt.FORMAT_GUIDE`）只告诉模型 QQ 能渲染哪些元素、平台有哪些限制，用不用、用哪些由模型自己决定；不规定什么场合用什么形式，也不要求闲聊只用纯文字（用户 2026-11-20 决定）。已实现：列出上面「Markdown」一条里的元素与嵌套列表的写法，HTML、链接、图片三条限制照旧。

### 先记下、还没实现的优化

用户 2026-11-20 决定要做，细节实现时再定：

1. **初次见面**：欢迎语下面只放一个按钮「你能做什么」，点了回一段固定的使用示例（不调用模型），用过之后就不再能用。不做底部的自定义菜单。
2. **单独发图或文件后的那句询问**（`texts.attachments_waiting()`）：加几个快捷按钮（如「描述一下」「提取文字」「翻译」「总结要点」）。用户点了其中一个，或接着发了消息之后，这组按钮就不再能用。
3. **确认类按钮**（忘掉话题、提醒的设置与取消）：用样式区分主次（删除用红字），同组点了一个之后另一个变灰，需要时加平台自带的二次确认弹窗。
4. **管理员的指令面板**：只对管理员生效的 `/` 面板，列出管理命令与说明。
5. **等待阶段**（「正在输入」与过程消息）不改。

### 按钮用过之后

平台没有修改或移除已发消息上的按钮的接口，所以第 1、2 条里的「消失」分两层做：

- 程序一侧一定做到失效：按钮带一次性的令牌，用过、过期或有了下文之后再点，不再起作用（沿用确认按钮的令牌机制；欢迎语的按钮可能隔很久才点，状态要存进数据库，不能只放内存）。
- 界面上能不能变灰或消失要实测：回调按钮的 `group_id`（文档说同组点了一个其余变灰，没说被点的那个，也没说只有一个按钮时怎样）；撤回只在发出 2 分钟内有效，还会留一条撤回提示，不合适。
- 因此这两处要用回调按钮，不能用「点了直接替用户发一句话」的指令按钮：后者发出后程序管不了，过多久点都会再发一遍。

## 待定：图片随回答发出

用户的想法（2026-11-20）：模型的回答里有示意图之类的图片地址时，机器人把图拖下来随回答一起发出。平台支持图片写在正文中间（见上），所以能做；下面是查证到的事实与还没定的事。与「模型输出里的图片语法」这个安全细节一起考虑（用户同意）。

图片地址从哪来：

- **模型自己写的 `![说明](地址)`**：两家都能写，位置由模型决定。地址可能是凭记忆编的，有多少是真的还没有实测。
- **OpenAI 搜索工具的图片结果**（2026-11-20 查自[官方指南](https://developers.openai.com/api/docs/guides/tools-web-search)的「Image search results」）：`search_content_types` 里加 `"image"`，`include` 里加 `web_search_call.results`，结果在 `web_search_call` 输出项里，每条有 `image_url`、`thumbnail_url`、`source_website_url`、`caption`。地址是真的，但与回答的正文分开给，放在哪由程序决定；文档的示例注明已发布的 SDK 还没有这几个参数。Gemini 的搜索没有图片结果（[官方指南](https://aistudio.google.com/docs/google-search)只有文字与 `url_citation`）。

为什么要由机器人下载，而不是把地址原样交给平台去抓：

- 平台的图片语法要写宽高，模型不知道图片的尺寸；下载后才能按真实的比例写。
- 模型写的地址可能打不开或不是图片，先下载才能把坏的去掉，不让用户看到裂图。
- 平台的服务器抓不抓得到境外网站的图没有实测；机器人这边可以走自己的网络或代理。
- 本地留一份，之后的轮次才能像用户发的图一样带给模型或写描述。

下载之后怎么发，三种做法各有没验证的地方：

| 做法 | 好处 | 问题 |
| --- | --- | --- |
| 写回原地址、补上宽高，由平台再抓一次 | 图在正文中间，不占额度 | 平台抓不到时用户看到什么没有实测；流式消息里没法要求「抓不到就整条失败」 |
| 传到素材库，正文里引用素材库的地址 | 图在正文中间，显示可靠 | 每个机器人最多 100 张，要删旧的；删掉之后已发的消息里图还在不在没有实测 |
| 作为单独的图片消息发（现在画图用的就是它） | 可靠，没有张数上限 | 不在正文里：要在图的位置结束当前的流式消息、发图、再开一条，每张图多占两次被动回复 |

安全上要一起做的：

- 现在模型输出里的图片语法只靠提示词禁止，程序没有拦（`markdown_guard.py` 只处理链接的括号）；平台会去抓其中的地址。
- 机器人自己下载时要防着请求内网：只收 https，解析出的地址是内网、回环、链路本地等一律拒绝，重定向之后重新检查，限制大小与时长，按文件头认格式（`media.detect_format()`）。附件下载现在靠的是 QQ 域名的白名单，这里用不上。
- 泄露：开着搜索时，网页里的注入内容可以让模型把对话里的信息拼进图片地址，谁去抓这个地址，信息就到了对方手里。只抓搜索工具自己给出的地址最稳，但那就不收模型自己写的地址；折中是不抓带查询串的地址、限制长度。取哪种没有定。

动手之前建议先做两个小实测（都没有做，按 `AGENTS.md` 先取得同意）：

- 模型一侧（计费）：把图片那条限制临时放开，开着搜索问两家各十来个适合配图的问题，数一数给出的图片地址有多少真的是图。命中率低的话，模型自己写地址这条路就不值得做。
- QQ 一侧（在 pyqbot 的实测里做）：单聊流式消息里放第三方网站的图；地址打不开时用户看到什么；不写宽高会怎样；素材库的图删掉之后，已发的消息里还在不在。

## 没有定

调研里提过、用户还没有表态的：

- 给模型一个「给出选项」的函数，回答之后由程序发一组按钮（做法同忘掉话题的确认：函数只登记，回答写完再发）。
- 出错与没写完时的「继续」「重试」按钮。
- `/users`、`/invites` 列表下的停用、撤销按钮；`/usage` 改成表格。
- 图表（服务商内置的代码执行出图，或本地渲染）。

## 还要实测的

- 回调按钮的 `group_id`、二次确认弹窗（`modal`）、红字样式在单聊里的实际表现（pyqbot 都还没有实测）。
- 指令按钮 `enter` 在单聊里点了之后实际发出的文字（pyqbot 的实测用例里有这个按钮，errata 只记了样式）。
- 按钮文字的长度上限（pyqbot 的 docstring 写 10 个字符）。
- 嵌套列表缩进 2 个空格时会不会被压平（官方只说要 4 个空格；管理员的 `/usage` 现在用的是 2 个空格）。
- 「图片随回答发出」一节列的四项。
