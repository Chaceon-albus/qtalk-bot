# 展示与交互

回答怎样排版，哪些地方用按钮与指令面板，网上的图片怎样随回答一起发出。过程消息与「正在输入」见 [search-and-process.md](search-and-process.md)，确认按钮现有的机制见 [memory.md](memory.md)。

目标是向 ChatGPT 的 Intelligent UI 那种富展示靠拢（模型从一套固定的原生组件里挑，客户端边生成边渲染；OpenAI 没有公开接口）。QQ 上能靠拢的主要是 Markdown 本身，交互只有按钮一种；凡是「点一下、原地变化」的（表单、计算器、标签页、小游戏）都做不了。

## QQ 侧能做到什么

出处是 pyqbot 的 `docs/guide.md`、`docs/errata.md` 与官方文档快照（`docs/upstream/qqbot-api-v2/`），以固定的那个 commit 为准。

- **Markdown**：官方「Markdown 消息」列的标题、文字样式（粗体、斜体、删除线）、链接、图片、有序与无序列表（可以嵌套）、块引用、分割线都能用；文档没列的代码块、表格（含对齐）、LaTeX、任务列表、脚注实测也能用，流式与普通消息的最终渲染一致（errata「Markdown：实际支持的语法比文档多」）。HTML 标签不生效，没有折叠。嵌套列表的子项要缩进 4 个空格，列表前面是普通文字时要先空一行（官方文档的「列表嵌套」）。
- **图片可以写在 Markdown 正文中间**：`![文字 #宽px #高px](地址)`，地址要能在公网访问，平台自己下载转存；流式消息里也能用。宽高必须写，并按原图的比例：不写时只显示「[文字]」，写错会变形。平台抓不到图时接口不报错，客户端显示「图片加载失败」。素材库（先上传、再引用 `qqbot-media://` 地址）每个机器人最多 100 张，但引用它的消息发完之后就可以删掉素材，已发的消息不受影响。细节见下面的[「QQ 一侧的实测」](#qq-一侧的实测2026-11-20)。
- **按钮只能随普通的 Markdown 消息发**，流式消息的请求体里没有键盘字段。三种按钮：回调（点了推一个互动事件）、指令（把一段文字填进输入框，`enter` 时直接以用户的身份发出，只有单聊）、跳转（https 链接）。回调按钮可以分组（同组点了一个，其余变灰）、带二次确认弹窗、选样式（线框、蓝底、红字）。
- **消息发出后不能修改**：单聊只有发送、流式发送、撤回三个接口。普通消息发出 2 分钟内可以撤回（聊天里留一条撤回提示），流式消息撤回不了。所以按钮发出后去不掉，「用过就消失」至多做到失效或变灰，见下面的[「按钮用过之后」](#按钮用过之后)。
- 点了回调按钮后的 `visited_label` 只是临时显示，收到下一条消息后按钮又显示回原来的文字（errata「回应互动」）。
- **指令面板**（输入 `/` 时弹出）可以只关联指定的用户（errata「指令面板」实测的就是只关联一个用户的单聊面板）；**底部的自定义菜单**对所有用户相同。

## 格式说明只列能力

系统提示词里的格式说明（`prompt.FORMAT_GUIDE`）只告诉模型 QQ 能渲染哪些元素、平台有哪些限制，用不用、用哪些由模型自己决定；不规定什么场合用什么形式，也不要求闲聊只用纯文字。它列出上面「Markdown」一条里的元素与嵌套列表的写法，以及 HTML、链接、图片三条限制。

## 按钮与指令面板

还没有实现。要做的四项：

1. **初次见面**：欢迎语下面只放一个按钮「你能做什么」，点了回一段固定的使用示例（不调用模型），用过之后就不再能用。不做底部的自定义菜单。
2. **单独发图或文件后的那句询问**（`texts.attachments_waiting()`）：加几个快捷按钮（如「描述一下」「提取文字」「翻译」「总结要点」）。用户点了其中一个，或接着发了消息之后，这组按钮就不再能用。
3. **确认类按钮**（忘掉话题、提醒的设置与取消）：用样式区分主次（删除用红字），同组点了一个之后另一个变灰，需要时加平台自带的二次确认弹窗。
4. **管理员的指令面板**：只对管理员生效的 `/` 面板，列出管理命令与说明。

等待阶段（「正在输入」与过程消息）不改。

### 按钮用过之后

平台没有修改或移除已发消息上的按钮的接口，所以第 1、2 条里的「不再能用」分两层做：

- 程序一侧一定做到失效：按钮带一次性的令牌，用过、过期或有了下文之后再点，不再起作用（沿用确认按钮的令牌机制；欢迎语的按钮可能隔很久才点，状态要存进数据库，不能只放内存）。
- 界面上能不能变灰或消失要实测：回调按钮的 `group_id`（文档说同组点了一个其余变灰，没说被点的那个，也没说只有一个按钮时怎样）；撤回只在发出 2 分钟内有效，还会留一条撤回提示，不合适。
- 因此这两处用回调按钮，不用「点了直接替用户发一句话」的指令按钮：后者发出后程序管不了，过多久点都会再发一遍。

## 图片随回答发出

已实现，还没有在真实的 QQ 上跑过（要实测的事见[「待实测」](#待实测)）。模型的回答里有网上的图片（示意图、照片、图表）时，机器人把图下载下来，传到素材库，在正文中间引用素材库的地址，这条消息发完就删掉素材。下载只抓白名单里的图站，见[「默认白名单」](#默认白名单)。

图片地址来自模型自己写的 `![说明](地址)`：两家都能写，位置由模型决定。实测里两家只在搜索过的回答里给图，给出的地址都对得上真实的图片（见[「模型一侧的实测」](#模型一侧的实测2026-11-20)）。

为什么由机器人下载，而不是把地址原样交给平台去抓：

- 平台的图片语法要写宽高，模型不知道图片的尺寸；下载后才能按真实的比例写。
- 模型写的地址可能打不开或不是图片，先下载才能把坏的去掉，不让用户看到「图片加载失败」。
- 平台的服务器抓不到维基共享资源的图，而模型给的图大多在那里；机器人这边可以走自己的网络或代理。

为什么传到素材库，而不是别的发法：

| 发法 | 取舍 |
| --- | --- |
| 传到素材库，正文里引用素材库的地址 | 用它：图在正文中间；流式消息结束后立刻删掉素材，已发的消息里图还在，所以不占 100 张的额度 |
| 写回原地址、补上宽高，由平台再抓一次 | 不用：维基的图平台抓不到，流式消息又不报错，用户只会看到「图片加载失败」 |
| 作为单独的图片消息发（画图用的就是它） | 不用：图不在正文里，每张图还要多占两次被动回复 |

程序要做的事：

- 流式输出到图片语法时先扣住，等这一段写完整。
- 下载、按文件头认格式、读出宽高。
- 传到素材库，把语法改写成 `![说明 #宽px #高px](素材库的地址)` 再交给流式消息。
- 这条流式消息结束之后删掉素材。不能提前删：引用已经删掉的素材时接口不报错，用户看到的是「图片加载失败」。所以流式消息没有确认结束（结束分片被拒或超时、有分片送达不明）时不立即删，留给定期清理：每小时一次，删掉文件名符合本功能的格式、上传超过 2 小时的素材；进程在上传与删除之间退出留下的也由它删。
- 删除按引用计数：平台可能把内容相同的两次上传合并成同一个素材，两条回答同时引用同一张图时，最后一条结束才删。
- 下载之前、上传之前各复查一次用户的授权：回答中途被停用的用户，之后的图不再下载。
- 任何一步失败就去掉这张图、留下说明文字，不让回答卡住。回答因为超时、出错、插话而停下之后，不再开始新的下载。
- 下载到期、或这张图已经用不上（这次调用的总时限到了、发送端不再接受内容）时，不再发起新的请求，在途的请求被取消，迟到的结果不采用、迟到的素材删掉。接受的边界：程序自己发起的关闭从不被取消，但取消恰好落在底层网络库在那次请求内部自己关闭响应或连接的那一刻（读写出错之后的收尾、站点返回写坏了的重定向地址时的关闭）时，那次关闭可能被打断，留下的连接由垃圾回收或关停时关闭客户端收掉。为这种很少出现的情况改成不取消（慢慢吐数据的图站会一直占着连接）、绕开客户端自己的重定向处理（会丢掉系统代理设置的支持）或每张图单独一个客户端都不值得。

安全：

- 模型输出里的图片语法一律由程序处理，不原样交给平台：平台会去抓其中的地址。能认成图片的走白名单；认不成的把感叹号换成全角的「！」，平台就不会当它是图片（`web_images.ImageScanner`）。
- 唯一的例外是代码块：把代码里的 `![` 换成全角会改坏代码（Rust 的 `#![no_std]`、正则的 `(?![a-z])`），所以顶格开头的反引号代码块里的内容原样放行。放行依赖平台也把这里当作代码块，而平台用的解析器没有公开，所以条件从严，三条都满足才放行，拿不准的一律不放行：
  - 按 CommonMark 逐字符判断，它确实是顶层、顶格的反引号代码块的内容。
  - 到这里为止全文是「规范形状」：代码块的开头行与结束行都是顶格的恰好三个反引号，开头行的上一行是空行（或它就是全文的第一行）。出现过任何别的写法（四个以上或别处的连续反引号、紧跟在一行正文后面的代码块、波浪线围栏、`$$`、`\[`、`\(`（写在代码块里的也算）、行首的 `<`、单独的回车、开头的 `---`）之后，这条回答不再放行。这样换成别的常见解析方式（用正则成对匹配反引号、只认三个反引号的围栏、不认波浪线围栏、把公式当作可以跨行的整段先取走、结束行后面允许跟别的字）来看，放行的内容也都在代码块里；这些解析方式是纵深防御，清单到此为止，平台实际怎样解析见「待实测」。放行另有一个去不掉的前提：平台把还没有结束行的代码块当作代码（流式消息的每个中间状态都是这样的代码块），同样要靠实测确认。
  - 在这条回答的前 12000 字节之内：平台把超过约 15000 字节的流式消息不看结构地硬切成几条气泡（见 [conversation.md](conversation.md) 的分条），切口落在代码块里时，后一条气泡里的内容就成了正文。
- 上面这个例外的代价：行内代码，缩进的、列表里的、波浪线的、四个以上反引号的、前面没有空行的代码块，回答里出现过公式或列表里的代码块之后的代码块，代码里出现过 `$$`、`\(`、`\[`（如正则表达式）之后的部分，以及长回答靠后的代码块里，`![` 会显示成全角感叹号。
- 原始 HTML 不处理：QQ 的 Markdown 不渲染 HTML 标签（pyqbot errata 测过 `<u>`、`<sup>`），`<img>` 会不会被加载见「待实测」。说明文字里的尖括号会换成全角，不经由程序拼出的文字带进标签。
- 泄露：开着搜索时，网页里的注入内容可以让模型把对话里的信息拼进图片地址，谁去抓这个地址，信息就到了对方手里。所以只抓白名单里的图站，其余的不抓。另两种做法没有用：只抓搜索工具自己给出的地址（最稳，但那就不收模型自己写的地址）；去掉查询串再抓、限制地址长度（挡不住把信息写进路径的，还会丢掉本来能用的图）。
- 下载不带 Cookie 与鉴权，每次重定向之后重查白名单，限制大小（按实际传输的字节数，不收再压缩过的响应）与时限，按文件头认格式。图片地址属于聊天内容，日志里最多写主机名。

### 默认值

| 项目 | 取值 |
| --- | --- |
| 开关 | 按模型设（`[[models]].web_images`），默认打开 |
| 每个回答的图数 | 不限 |
| 单张大小 | 不超过 10 MB（素材库的上限） |
| 下载时限 | 10 秒，超时就去掉这张图 |
| 维基的原图地址 | 改写成缩略图地址再下载：依次试 960、500、330、250、120px，都不行再试原地址 |
| 代理 | 图片下载单独设代理（`[web_images].proxy`），与 `[qq].proxy`、`[providers.*].proxy` 互不影响；不设就不走代理，系统的代理环境变量照常生效 |
| 显示大小 | 按原图的比例，长边不超过 512px，比它小的图不放大 |
| 名单外的地址，下载或上传失败 | 去掉图，留下说明文字；被跳过的主机只记日志 |
| 提示词 | 开关打开的模型，把「不要插图片」那条换成「可以用 `![说明](图片的完整 https 地址)` 把网上真实存在的图片插在正文里合适的位置；只用你确实知道存在的图片地址，不要编造」；这次请求还能画图时再接一句「要画一张新图时仍然用画图函数」 |

- 显示大小取 512px：实测里 300×200 的图显示正常，540×258 与 505×165 两张没有记下异常，2160×1032 被压扁；官方文档的示例写到 `#800px #400px`。所以 512 应该在安全的范围里，但开始变形的界限没有测过，第一次用的时候要看一眼效果，所以做成可以调的配置项。限制的是长边：竖着的图按宽度取 512 会很高。
- 为了单独设代理，图片下载用自己的 HTTP 客户端，`httpx2` 因此是直接依赖（它本来就随 pyqbot 装着）。

### 默认白名单

下载只抓主机名落在白名单里的地址：主机名等于某个后缀，或以「.后缀」结尾。入选的标准是这个后缀下只有站点自己（或按注册规则只有某一类机构）能提供内容、看到请求。共 27 个后缀：

| 类别 | 后缀 |
| --- | --- |
| 政府与国际组织 | `gov.cn`、`gov`（美国）、`gov.uk`、`gouv.fr`、`gov.ru`、`int`（条约设立的国际组织）、`un.org`（联合国）、`europa.eu`（欧盟机构） |
| 百科、开放教材与数据 | `wikimedia.org`、`openstax.org`、`ourworldindata.org` |
| 科研与教育机构 | `edu`、`edu.cn`、`cas.cn`（中科院）、`cern.ch`、`esawebb.org`、`eso.org`、`nobelprize.org` |
| 博物馆 | `dpm.org.cn`（故宫）、`chnmuseum.cn`（国博）、`louvre.fr`、`metmuseum.org`、`britishmuseum.org` |
| 国内官方媒体 | `news.cn`、`xinhuanet.com`、`people.com.cn`、`chinadaily.com.cn` |

- 政府后缀只收联合国安理会五个常任理事国的。各国的政府站并不都在这些后缀下，不在的不放。
- 联合国系统里，世卫组织、气象组织、国际电联等用 `int` 的已经在内；教科文组织、儿基会、粮农组织等用的是各自的域名，没有收。
- `gov`、`int`、`edu` 是单段的后缀，只在内置名单里用。匹配按整段比较：`gov` 不会命中 `gov.au`，`edu` 也不会命中 `edu.cn`（它是单独列的）。配置里追加的项仍要求至少两段。
- `edu` 与 `edu.cn` 比政府后缀弱一档：大学会把子域名与个人主页分给院系和个人，能看到请求的人更多。
- 国内官方媒体的图可能带水印，版权归各家所有。
- 不在名单里的几类：多租户的云存储与内容平台（`amazonaws.com`、`sitecorecloud.io`、`ctfassets.net`、`bcebos.com` 等，任何人都能在这些后缀下开一块地方并看到访问记录）、图库、品牌官网。
- 在[图站调研](#图站调研2026-11-20)的 108 张图里，这份名单覆盖 94 张（87%）：`gpt-6.2-sol` 82%，`gemini-4-hydrogen` 92%。
- 调研里没有出现过、按站点的性质放进来的：`gov.uk`、`gouv.fr`、`gov.ru`、`un.org`、`ourworldindata.org`、`edu.cn`、`cas.cn`、`cern.ch`、`chnmuseum.cn`、`metmuseum.org`、`britishmuseum.org` 与国内官方媒体的四个。这些站的图片文件可能放在别的域名上，要遇到了才知道名单写得对不对。
- 名单可以由配置追加（`[web_images].extra_hosts`），做法同 `[attachments].extra_download_hosts`。

### 模型一侧的实测（2026-11-20）

把格式说明里「不要插图片」那条换成上面默认值表里的那句，系统提示词只有人设、格式说明与当前时间，没有画图函数。两家都按本地配置开着搜索，各问 10 个固定的问题（不含用户数据）：5 个明说要图（光合作用、TCP 三次握手、心脏结构、勾股定理的证明、埃菲尔铁塔），5 个没说但适合配图（水循环、有丝分裂、行星大小、二叉搜索树的插入、板块构造）。再由脚本逐个下载回答里的图片地址，按文件头判断是不是图片。20 次调用都正常结束，共搜索 20 次。

| 模型 | 明说要图的 5 问 | 没说要图的 5 问 | 给出的图片地址 |
| --- | --- | --- | --- |
| `gpt-6.2-sol`（`reasoning = "high"`） | 3 个回答带图，各 1 张 | 都没有图 | 3 张都下载到了真的图片 |
| `gemini-4-hydrogen`（`reasoning = "medium"`） | 4 个回答带图，各 1 张 | 1 个回答带图 | 5 张里 4 张是真的图片，1 张被图站限流（HTTP 429） |

- **没有编造的地址**：8 张图全部出在搜索过的回答里；没搜索的 10 个回答都没有给图。被限流的那一张是维基共享资源上的原图，同一个文件的缩略图地址在另一家的回答里下载成功，所以文件是存在的。
- **要了图却没有给图的 3 个回答**（`gpt-6.2-sol` 的 TCP 三次握手与勾股定理，这两问它没有搜索；`gemini-4-hydrogen` 的勾股定理）都改用代码块里的字符画和 LaTeX 来讲，没有硬凑一个地址。
- **不主动配图**：没说要图的 10 个回答里只有 1 个带图。
- **位置与说明**：图都放在正文靠前或中间、紧跟引出它的那句话，说明文字是中文、写得具体；都没有写宽高。`gpt-6.2-sol` 每张图下面自己加了一行图源与授权（如「图源：维基共享资源，CC BY-SA 3.0」）。
- **图站**：7 张在维基共享资源（6 张是 `thumb.wikimedia.org` 的缩略图，SVG 的示意图已转成 PNG；1 张是 `upload.wikimedia.org` 的原图），1 张在 NASA。格式是 PNG 与 JPEG，51 KB 到 313 KB。
- **局限**：只有一次、20 个回答、8 张图，问题都是百科里常见的内容；冷门内容没有测。脚本与原始回答没有放进仓库。

### QQ 一侧的实测（2026-11-20）

用例是 pyqbot 的 `tests/live/test_live_markdown_images.py`，结论记在它的 `docs/errata.md`「Markdown 图片：不写宽高不显示，抓不到时显示「图片加载失败」，接口不报错」与「素材库：流式消息里可以引用，发出后删掉素材不影响已发的消息」（pyqbot 提交 acc6abf、3cbcd66，比本仓库固定的那个 commit 新）。单聊，测试用户发编号，机器人回一条正文中间带图的消息，15 种都做了：

| 情况 | 接口 | 用户看到的 |
| --- | --- | --- |
| 流式，维基共享资源的图 | 各分片都被接受 | 图片加载失败 |
| 流式，地址是 404、是网页、主机解析不了 | 各分片都被接受 | 图片加载失败 |
| 普通消息，地址是 404 | 被接受 | 图片加载失败 |
| 普通消息，地址是 404，打开强制校验 | 被拒，`err_code` 40034141「图片转存失败，请重试」 | 没有消息 |
| 流式，不写宽高（公网的图、素材库的图各一次） | 各分片都被接受 | 不显示图片，只显示「[说明]」 |
| 流式，540×258 的图写成 300×300 | 各分片都被接受 | 图片被拉伸 |
| 流式，同一张图写成 2160×1032（比例没变） | 各分片都被接受 | 图片被压扁 |
| 流式，素材库的图，结束后立刻删掉素材 | 上传、各分片、删除都被接受 | 发出编号后就退出聊天，等发完、删完再进入，图片显示正常 |
| 流式，引用已经删掉的素材 | 各分片都被接受，没有报错 | 图片加载失败（两次都是） |
| 流式，百度的图、NASA 的图（地址带查询串）；普通消息加素材库的图 | 都被接受 | 没有记下观察（显示失败的几种都记了） |

### 图站调研（2026-11-20）

脚本与提示词同模型一侧的实测。两家各问 40 个明说要图的固定问题，分 14 类题材（科学示意图、人体、动植物、国外地标、国内题材、人物与艺术、天文、工程图示、数学、产品与品牌、美食、地图、数据图表、近期时事），共 80 次调用，全部正常结束。

- **每个回答都搜索了、都给了图**：共 108 张，`gpt-6.2-sol` 49 张，`gemini-4-hydrogen` 59 张；一个回答 1 到 4 张，多数是 1 张。
- **104 张是真的图片**，格式都是素材库收的（JPEG、PNG、GIF、WebP，没有 SVG 与 AVIF），最大 7.6 MB。另外 4 张：1 张 404（`gpt-6.2-sol` 写错了维基的路径），2 张 400（`gemini-4-hydrogen` 自己拼的 800px 缩略图地址），1 张地址中间夹了「 ↗」（`gemini-4-hydrogen`）。

| 图站 | `gpt-6.2-sol` | `gemini-4-hydrogen` | 在白名单里 |
| --- | --- | --- | --- |
| `wikimedia.org` | 26 | 49 | 在 |
| `nasa.gov`、`cdc.gov`、`stats.gov.cn`、`cnsa.gov.cn`、`si.edu`、`wisc.edu`、`wmo.int`、`europa.eu`、`esawebb.org`、`eso.org`、`openstax.org`、`louvre.fr`、`dpm.org.cn`、`nobelprize.org` | 14 | 5 | 在 |
| 多租户的云存储与内容平台：`sitecorecloud.io`、`amazonaws.com`、`ctfassets.net` | 3 | 1 | 不在 |
| 其它：`qcloudimg.com`、`reutersconnect.com`、`nipr.ac.jp`、`geog.com.cn`、`unsplash.com`、`staticflickr.com`、`futurecdn.net`、`apple.com`、`apple.com.cn`、`byd.com` | 6 | 4 | 不在 |

- **两家的习惯不同**：`gpt-6.2-sol` 更常用原始出处（数据图表一类完全不用维基，中国题材会用故宫、国家统计局、国家航天局的站）；`gemini-4-hydrogen` 几乎全靠维基。新浪、搜狐、百度、知乎这类国内的内容站一张也没有出现。只放 `wikimedia.org` 的话，两家的覆盖率分别是 53% 与 83%。
- **维基的原图地址会被限流，缩略图地址不会**：`upload.wikimedia.org` 上的 46 张里有 26 张原图（全部来自 `gemini-4-hydrogen`）在两遍检查里都是 HTTP 429；`thumb.wikimedia.org` 的 29 张从没被限流。把这 26 张的地址改写成 960px 的缩略图地址后全部下载成功（15 KB 到 418 KB）。改写规则：`upload.wikimedia.org/wikipedia/<项目>/<a>/<ab>/<文件名>` → `thumb.wikimedia.org/wikipedia/<项目>/thumb/<a>/<ab>/<文件名>/960px-<文件名>`，SVG 再加 `.png`；缩略图不能比原图宽，960 不行时要退到更小的宽度（这次没有遇到）。
- **下载上要注意的**：用一个说明身份的 User-Agent（不放个人信息）；国内的政府站点从境外访问很慢（国家航天局那张超过 20 秒），10 秒的时限会丢掉这类图。
- **局限**：每题只问一次，每类题材 2 到 4 题，只出现一两次的图站占比不稳定；每题都明说要图，所以「每个回答都给图」不代表平时的行为（平时见模型一侧的实测：不主动配图）。「只有站点自己能看到请求」是按各站的性质判断的，没有逐个核实。

## 实施

范围是上面两节：图片随回答发出，以及按钮与指令面板的四项。「待定」里的不在范围内。

方式：

- 代码由子代理来写（Opus 5.5，推理强度 high），主会话监督，子代理不提交。
- 评审用 `gpt-6.2-sol`（推理强度 xhigh）。评审过、三项检查全过之后由主会话提交。
- GPT 的额度用完时改用 Opus 5.5（推理强度 xhigh）评审；只经过它评审的代码不提交，留在工作区，等 GPT 评审过再提交。

顺序：

1. **图片随回答发出**：已实现。不联网的部分（白名单与主机匹配、维基地址的改写、读宽高、流式输出里识别图片语法、配置项）在 `web_images.py`，接线（下载、素材库的上传与发完之后的删除、提示词、失败时退到说明文字）在 `image_download.py`、`conversation.py`、`bot.py`。
2. **确认类按钮**的样式、分组与二次确认。先在 pyqbot 里实测回调按钮的 `group_id`、`modal` 与红字样式。
3. **单独发图或文件后的快捷按钮**。
4. **欢迎语的「你能做什么」按钮**。
5. **管理员的指令面板**。

- 要不要另外用 OpenAI 搜索工具的图片结果（2026-11-20 查自[官方指南](https://developers.openai.com/api/docs/guides/tools-web-search)的「Image search results」）：`search_content_types` 里加 `"image"`，`include` 里加 `web_search_call.results`，结果在 `web_search_call` 输出项里，每条有 `image_url`、`thumbnail_url`、`source_website_url`、`caption`。地址是真的，但与回答的正文分开给，放在哪要由程序决定；文档的示例注明已发布的 SDK 还没有这几个参数。Gemini 的搜索没有图片结果（[官方指南](https://aistudio.google.com/docs/google-search)只有文字与 `url_citation`）。

## 待实测

- 回调按钮的 `group_id`、二次确认弹窗（`modal`）、红字样式在单聊里的实际表现（pyqbot 都还没有实测）。
- 指令按钮 `enter` 在单聊里点了之后实际发出的文字（pyqbot 的实测用例里有这个按钮，errata 只记了样式）。
- 按钮文字的长度上限（pyqbot 的 docstring 写 10 个字符）。
- 嵌套列表缩进 2 个空格时会不会被压平（官方只说要 4 个空格；管理员的 `/usage` 用的是 2 个空格）。
- 点了回调按钮之后，能不能用互动事件作被动回复的对象发「正在输入」与流式消息（决定快捷按钮触发的回答挂在哪条消息上）。
- `<img src=…>` 这类 HTML 标签在 QQ 里会不会加载图片（程序没有处理原始 HTML）。
- 反斜杠转义的 `\![…](…)`、全角感叹号的「！[…](…)」在 QQ 里会不会显示成图片（程序把认不成图片的感叹号都换成了全角）。
- 代码块的原样放行所依赖的几件事：流式消息写到一半、代码块还没有结束行时，里面的图片语法显示成代码还是图片，结束时仍没闭合呢；超长的流式消息被平台拆开、切口落在代码块里时，后一条气泡怎么渲染；波浪线围栏、`\[` 与 `$$` 里夹着反引号行、行中间的三个反引号、反引号后面跟着别的字的行、前后没有空行的代码块各自怎么渲染（程序都按最保守的情况处理了，实测之后可以放宽或还要收紧）。
- 同样内容的图上传两次是不是同一个素材（程序按会合并处理）。
- 图片：百度与 NASA 那两种的图有没有显示出来；图是在流式过程中出现还是结束后才出现，图是回答的第一段内容时怎样；512px 的横图与竖图显示的效果，宽高写到多大开始变形；流式消息还没结束就删掉素材会怎样，流式消息异常结束之后留着的素材还能不能显示。

以上除了图片的几项，用例都在 pyqbot 的 `tests/live/test_live_button_variants.py` 与 `test_live_upload.py::test_media_image_same_content_twice`。
