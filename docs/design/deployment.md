# 部署与运维

部署（里程碑 9）：数据保护、镜像与 compose、健康检查、备份、告警，以及给管理员的提醒模块。数据目录与数据库文件的权限见 [storage-and-config.md](storage-and-config.md#存储) 的「存储」。给运维者看的操作步骤在仓库的 `docs/deploy.md`。

部署到一台 Debian 的 VPS，用 docker compose。pyqbot 开发与部署都从 GitHub 安装，固定到某个 commit（见 [README](README.md#已定) 的「部署」一行）。

## 数据保护

数据去留另议，见[「其它待定」](open-questions.md#其它待定)。

- 不在程序里加密数据库：机器人运行时要读它，密钥只能和数据库放在同一台机器上，挡不住主机被攻破。只防数据库文件单独外泄的话，下面两条更划算，也不用新增依赖。
- 备份放在数据目录下，本项目不做备份加密。备份离开本机（异地、云存储）时由运维者自己加密，密钥不和备份放在一起；部署说明里写明这一点。
- 部署说明写明主机要开全盘加密（服务器的加密卷），数据目录放在加密的卷上。

## 镜像与 compose

- `Dockerfile` 两段构建，基础镜像都是 `python:3.14-slim-trixie`（与主机同为 Debian）。
  - 构建段装 git（pyqbot 是 git 依赖），从 `ghcr.io/astral-sh/uv` 复制固定版本的 uv，用 `uv sync --locked --no-dev --no-editable` 装进 `/app/.venv`。先只拷 `pyproject.toml`、`uv.lock` 装依赖，再拷源码装本项目，好利用层缓存。
  - 运行段只复制虚拟环境，另装 `tzdata`：配置里的时区要靠系统的时区数据，不新增 Python 依赖。
  - `QTALK_CONFIG` 写在 `Dockerfile` 的 `ENV` 里。
- 用非 root 账户运行，uid 与 gid 默认 1000，可以用构建参数改。宿主机上的 `data/` 要属于这个 uid。uid 与 gid 写在 compose 的 `build.args`，不放进 `.env`：`.env` 只放密钥。
- `.dockerignore` 用白名单写法：只放进 `pyproject.toml`、`uv.lock`、`README.md` 与 `src`，镜像里不带密钥（`.env`）、配置（`config.toml`）、用户数据（`data/`）、`.git`、`.venv`、测试与文档。
- `compose.yaml` 只有一个服务 `bot`：
  - `restart: unless-stopped`，`init: true`。
  - `stop_grace_period: 30s`：程序自己的关停总时限是 15 秒，docker 默认 10 秒就强杀，不够。
  - 密钥经 `environment:` 逐项从 `.env` 注入，与 `.env.example` 一一对应（`tests/test_deploy_files.py` 用纯文本核对）。
  - `config.toml` 只读挂到 `/app/config.toml`（`QTALK_CONFIG` 指向它），`./data` 挂到 `/app/data`。
  - 日志用 json-file 驱动，单个文件 10 MB，保留 5 个。
  - 不开端口：机器人只往外连。
- 进程退出（包括网关无法恢复时 pyqbot 抛错）由重启策略拉起。docker 不会因为「不健康」重启容器，健康状态只供 `docker ps` 与外部监控看。
- 日志照旧只写标准输出，由 docker 的日志驱动轮转，默认不记消息正文。

## 健康检查

心跳与健康检查在 `health.py`。

- **心跳**：主程序每 30 秒写一次心跳文件 `<数据目录>/heartbeat.json`，先写临时文件再改名。每次写之前在数据库线程上做一次限时 5 秒的 `SELECT 1`：事件循环或数据库卡住时，心跳就停了。
  - 启动时在打开数据库之前删掉上次留下的心跳文件；心跳任务在取机器人名字之前就开始。
  - 内容是 `{"updated_at": <Unix 秒>, "gateway": {"state": …, "elapsed_seconds": …}}`：网关部分记阶段与处于这个阶段的秒数（pyqbot 的单调时钟），不记要两边时钟相减的时间点。读网关状态出错时只是不写网关部分。
- **判定**：`python -m qtalk_bot.health` 按同一份配置找到心跳文件，健康时退出码为 0，否则为 1。它不连网络，不读密钥。
  - 心跳超过 90 秒没更新不健康；心跳时间比当前时间晚 30 秒以上也算不健康（时钟被往回调后，停掉的心跳不能一直显示健康）。
  - 网关：CONNECTED 健康；DISCONNECTED 与 NOT_STARTED 超过 `[alerts].gateway_down_minutes` 不健康（启动卡在取机器人名字等步骤、迟迟没走到 `bot.start()` 时，最终也会变成不健康）；STOPPED 不健康；没有网关部分、认不出的阶段或坏数据，网关按未知处理、不判失败。
  - 配置有误时也返回 1：docker 只认 0 和 1。
  - `health.py` 不导入 pyqbot，阶段的取值用本地常量，有测试核对它们与 `pyqbot.GatewayState` 一致。网关状态来自 pyqbot 的 `Bot.gateway_status`（pyqbot 35093b6 起有）；不去解析 pyqbot 的日志。
- `Dockerfile` 的 `HEALTHCHECK`：每 30 秒一次，超时 10 秒，启动宽限 60 秒，连续 3 次失败算不健康。

## 备份

备份的命名、列举、轮转、磁盘余量、迁移前备份的钩子、定时备份 `BackupScheduler` 与磁盘检查 `DiskWatch` 在 `maintenance.py`。

- 放在 `<数据目录>/backups/`，目录权限 0700。用 `Database.backup()`：SQLite 在线备份，先写独占的临时文件再改名，文件权限 0600。复制每步 1024 页，每步之前检查放弃信号；`Database.backup()` 被取消时设置这个信号，临时文件随之删掉。
- 启动时（打开数据库之前）清掉 `backups/` 里本程序留下的 `.partial` 临时文件（SIGKILL 的残留，里面有用户数据），只认备份命名对应的临时文件名。
- **定时备份**：
  - 文件名带 UTC 时间，`qtalk-YYYYMMDDTHHMMSSZ.db`。
  - 启动 5 分钟后看最新的一份，距今超过 `[backup].interval_hours`（默认 24）就做一份，之后按最新一份的时间排下一次。排程只看文件名时间不在未来的最新一份，一份都没有就立即备份；调度在「下一次备份」与「最老一份超龄」中较早的时刻醒来。
  - 保留最新的 `[backup].keep` 份（默认 7），多的删掉；另有年龄上限 `keep × interval_hours`（默认 7 天），超龄的每次调度醒来都清理，新的备份一直失败时也照删。只认符合命名的文件，别的文件不碰。轮转保护本次刚写成的那一份，并排除当前数据库的真实文件（按设备号与 inode 比较）。
  - 清理（超出份数与超龄）和做新备份各管各的：新备份失败按备份失败告警（键 `backup`）；删不掉旧备份、列不出目录等清理失败另行按清理失败告警（键 `backup-cleanup`），不算备份失败。两者都 1 小时后重试，任务不退出；清理失败不挡到期的新备份，新备份失败后的退避也不推迟超龄的清理。因关停而放弃的备份只记日志，不告警。
- **迁移前备份**：打开已有的数据库、要升级表结构时，先备份成 `qtalk-before-v<旧版本>-<UTC 时间>.db`，最多保留最近 3 份，不计入定时备份的份数，也没有年龄上限。新建的空库不备份。
  - 经存储层的钩子 `BeforeMigration` 做：存储层不知道 `backups/` 目录。
  - 这份备份失败就不迁移，按「数据库有误」退出，不告警。做成之后轮转出错只记警告，不挡迁移。
  - `Database.open` 被取消时备份放弃；备份完、进入迁移之前再查一次，已取消就不升级。
- **磁盘余量**：做备份之前看磁盘余量，剩余空间不到主库文件大小的 2 倍（不含 `-wal`）时不做，按备份失败处理。
- 维护的文件操作（建目录、扫描、轮转、磁盘与文件大小、心跳的读写删）都经 `asyncio.to_thread`。
- 备份里有用户已经要求忘掉的内容：定时备份里最多再留 `keep × interval_hours`（默认 7 天）；迁移前备份没有年龄上限，一直留到被之后的迁移前备份挤掉（见[「已知的薄弱处」](open-questions.md#已知的薄弱处)）。
- 恢复的步骤写进部署说明：停容器，把备份复制成 `qtalk.db`，删掉旁边的 `-wal`、`-shm`，再启动。

## 告警

告警有四种：网关断开、模型额度用尽或连续失败、备份失败、磁盘空间不足。都经 [`alerts.py`](#给管理员的提醒alertspy) 发。

- **键**：`gateway`、`model:<服务商>:<模型名>`、`backup`、`backup-cleanup`、`disk`。「已恢复」是 `<键>:已恢复:<第几次告警>.<第几次补发>`，每次各用一个，免得被之前的「已恢复」的冷却挡住。
- **告警与恢复**（`alerts.Incident`）：发出过告警的情况恢复后补一条「已恢复」：网关重新连上（附断开了多久）、这个模型又成功了一次、下一次备份或清理成功、磁盘空间回到阈值以上。
  - 只在这次的告警真的发出去了时才补：原告警还在发送中就恢复了的，等确认发出后再补；原告警没发出去就不补。
  - 被每小时限额挡下的「已恢复」留着：按 `Alerts.room_in()` 算出限额窗口腾出名额的时刻，经 `Alerts.call_later()` 到时主动重试，又被挡下就按新的时刻再排；下一次 `resolve()` 也会立即再试。
  - 恢复后又出事，撤回还没发出的「已恢复」并取消重试；「已恢复」已经在发的，取消那个发送任务（已经开始发的，不保证管理员收不到）。关停时一并取消。
  - 「发出去了没有」由 `alerts.notify(on_delivered=...)` 在发送结束时回调，挂在任务的完成回调上，任务没开始就被取消也回调一次。
- 启动后 5 分钟内不查磁盘、不补做备份：告警的冷却只记在内存里，重启就清空，这样崩溃重启的循环不会每次启动都发一遍。模型的告警要先累积失败次数，不受影响。

### 网关

`gateway_watch.py`：

- 每 30 秒读一次 `bot.gateway_status`，DISCONNECTED 处于当前状态的时长达到 `[alerts].gateway_down_minutes`（默认 10）时告警。同一次断开只告警一次。
- 再看到 CONNECTED 时补「已恢复」，写明断开、连上的时刻（按配置的时区）与断开了多久。
- 一次故障只有一个时间基准：第一次看到断开超过门槛时，记下单调时钟上的起点（现在的单调时间减快照的 `elapsed`，pyqbot 的 `elapsed` 也按本进程的单调时钟计）与断开的起始时刻（快照的 `since`，只用来显示）。告警（包括被限流、下次检查再试的）与「已恢复」都从这个起点算时长；连上的时刻是现在的单调时间减 CONNECTED 快照的 `elapsed`。不拿墙上时钟相减，系统时钟被调过也不受影响；显示的时刻用快照的 `since`。
- NOT_STARTED 与 STOPPED 不告警。两次检查之间的短暂断连看不到，也不告警；同一次故障里没看到的短暂重连再断开，告警与「已恢复」都从最初那次断开算起。
- **已知的边界**（接受）：网关遇到无法恢复的关闭码时 pyqbot 抛错、进程退出、容器反复重启，每次都活不到告警的门槛，所以不会有网关告警，健康检查也可能来不及变成不健康；这时要看 `docker compose ps` 的重启次数与日志。不另做持久化的告警。

### 模型

`model_watch.py`：

- **统计范围**：按服务商加服务商那边的模型名统计，几个用途共用一个模型时合在一起。所有用模型的地方都算：对话、决策、图片描述、摘要与档案、出图。观察点在 `ChatModels(observer=...)`：给了就把它创建的所有模型包一层，调用点不用改。
- **立即告警**：鉴权失败（401、403）；额度用尽：OpenAI 返回 `insufficient_quota`，Claude 返回 HTTP 402 或错误体的 `type` 是 `billing_error`（含流里的 `error` 事件）。额度用尽是 `ModelError.quota_exhausted`（OpenAI 看 SDK 的 `APIError.code == "insufficient_quota"`），不加新的 `ErrorKind`，面向用户的回复与决策记录不变。
- **连续失败**：其它失败（连接失败或超时、限流、服务端出错、生成失败、响应不完整、其它）连续 `[alerts].model_failures` 次（默认 5）、中间没有一次成功时告警。
- **成功与失败的判定**：
  - 对话的流：`COMPLETED`（不是拒答）与 `MAX_TOKENS`（写到输出上限，服务本身是好的）算成功。`OTHER`（内容过滤、Gemini 的不完整、原因不明）与拒答两边都不算，不计数也不清零。Gemini 的不完整多半是输出预算写满，流里又没有具体原因，算失败会误报，所以不计入。OpenAI 的纯拒答以 `COMPLETED` 结束，所以 `llm.Finished` 有 `refused`（只有正文是 refusal 时为真），面向用户的行为不变。Claude 的拒答按[「出错时」](conversation.md#出错时)的映射，不论哪种都不计入。
  - 决策：至少一题正常作答才算成功，全部拒答或解析失败两边都不算。
  - 抛 `ModelError` 算失败：备用模型接手成功时，主模型照样记一次失败。被取消（被插话或关停取消）、调用方中途关掉流、`ModelError` 之外的异常都不算。
  - 不计入失败的错误：被安全策略拦截、出图被内容审核拦下、拒答、不支持的输入、其它 4xx（多半是输入的问题）。
  - OpenAI 的 `ResponseError.code` 里图片输入有问题的 13 个码归为 `BAD_REQUEST`，内容策略类的 4 个（`image_content_policy_violation`、`bio_policy`、`misalignment_policy_violation`、`invalid_prompt`）归为 `BLOCKED`，都不计入连续失败。面向用户的回复不变：对话遇到任何 `ModelError` 都换备用模型、最后回同一句话，不看分类。有测试核对 SDK 的取值列表里还有哪些码没有映射，SDK 增加新码时会提醒。
- **程序自己的时限**到期按连接超时计入，经 `model_watch.report_timeout(model)` 上报：对话的空闲时限、选模型与插话判断、图片描述、摘要与档案。
  - 对话只报空闲时限：服务商挂死时它一定先到，执行函数期间它是暂停的；总时限到期也可能是函数工具或这一轮前面的步骤把预算用掉了，不算在模型头上。
  - 图片描述、摘要与档案已经收到结局、只是关闭流时超时的不报。出图的时限在出图器里，超时本来就转成 `ModelError`。
- 模型告警属于 `AlertGroup("模型", 5)`，每小时最多 5 条，它的「已恢复」也算在这一组里。
- 文案写服务商、模型、错误分类与状态码，不写请求内容。

### 备份与磁盘

- **备份**：定时备份失败就告警（迁移前备份失败时直接退出，不告警）；清理旧备份失败另行告警，见[「备份」](#备份)。
- **磁盘**：每 10 分钟查一次数据目录所在文件系统的剩余空间，低于 `[alerts].disk_free_min_mb`（默认 1024）时告警；`disk_free_min_mb = 0` 表示不查磁盘。

## 配置

`[backup]` 与 `[alerts]` 两个表都是可选的，不写就用默认值，配置项同步写进 `config.example.toml`。范围：`interval_hours` 1–8760，`keep` 1–365，`model_failures` 1–100，`disk_free_min_mb` 0–1048576，`gateway_down_minutes` 1–1440。

## 关停

`_shut_down()` 的第 0 步排在 `Batcher.stop()` 之前：同步停掉心跳、定时备份（设置放弃信号）、磁盘检查与网关检查，再取消任务，免得备份占着唯一的数据库线程、挤掉前台入库的时间；等它们退出在第 8 步，受总时限约束。

已接受的边界：经 `asyncio.to_thread` 的文件操作在挂载卷卡死时取消不了，取消的只是外层协程，`asyncio.run()` 退出时仍会等默认执行器里的线程，容器可能一直等到 docker 的 30 秒停机宽限后被强杀（不改代码，写进了部署说明）。

## 部署说明

`docs/deploy.md` 写给运维者，内容包括：在 Debian 上装 docker（指向官方文档）、取代码、准备 `.env` 与 `config.toml`、`data/` 的属主、启动与看日志、看健康状态、升级（含升级 pyqbot 固定的 commit）、从备份恢复，以及异地备份自己加密、主机开全盘加密。

## 给管理员的提醒（`alerts.py`）

可复用的提醒模块，第一个用途是[下载域名的提醒](attachments.md#下载与白名单)，上面的告警也用它：

- `alerts.notify(键, 文案)`：同步调用，立即返回是否安排了发送；在后台给 `ADMIN_OPENID` 发一条主动消息。
- 同一个键 24 小时内只发一次（记在内存里，重启后可能再发一次）；全局每小时最多 10 条，免得耗光平台的主动消息额度；同一类提醒还可以另设更小的每小时上限（`AlertGroup`，下载域名一类是 3 条，模型一类是 5 条），免得一类提醒挤掉别的。被上限挡下的不占冷却；发出但失败的照样占冷却（多半是额度用尽）。每次发送最多 10 秒，超时就放弃。
- 发送失败只记日志，不影响触发它的流程；关停时在关闭 QQ 客户端之前等在发的提醒，之后触发的直接丢弃。
- 键和文案里不能放完整链接、路径、查询串或 openid。
