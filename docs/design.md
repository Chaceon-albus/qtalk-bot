# 设计

总约束见根目录 `AGENTS.md`。本文记录方向、已经定下来的决定和还没定的事。

**还没有任何实现。** 「已定」一节是用户确认过的；其余各节写的是方向和建议，实现到那一步时先和用户确认细节，不要当成既定事实照着做。

## 目标

- 管理员在聊天里生成邀请链接，经链接添加机器人的用户可以和大模型对话。
- 对用户无感：QQ 与机器人的单聊只有一个会话，不让用户用 `/new`、`/list` 这类命令管理 session，分段与回溯由机器人自己完成。
- 能在 2 核 2G 的机器上跑起来。

要支持的能力，由简到繁：

1. 用户提问，大模型回答。
2. 按消息的性质选模型：先做一次分类，再交给对应类别的模型（例如解决问题用一个，情感支持用另一个）。类别与模型的对应关系是配置出来的列表。
3. 语音输入：模型支持音频就原样给，不支持就先转成文字。
4. 多个输入对应一次提问：一条消息里同时有图片和文字；先发图片或文件，再用文字或语音提问。
5. 话题回溯：聊过 A，又聊了 B、C，再回到 A 时能带上 A 的上下文，同时知道 B、C 的存在。
6. 提醒事项：「提醒我 / 告诉我 / 帮我……」，到点由机器人主动发出。
7. 联网搜索：直接用服务商内置的搜索工具，本项目不自己实现搜索。
8. 展示处理过程：模型思考、搜索时让用户看到进展，类似 ChatGPT 的思考摘要。

## 已定

| 事项 | 决定 |
| --- | --- |
| QQ 侧 | 只经由 pyqbot |
| 部署 | docker compose：机器人本体加其它服务 |
| 密钥 | 环境变量，由 `.env` 经 compose 的 `environment:` 逐项注入，每个服务只拿自己需要的 |
| 静态设置 | TOML 配置文件：模型列表、决策提示、各种时长与配额 |
| 运行时会变的数据 | 数据库：授权名单、邀请令牌、对话与记忆 |
| 大模型调用 | 官方 SDK：`openai`、`google-genai`（这两个依赖已获同意） |
| 选模型 | Decisions API；OpenAI 与 Gemini 两家都适配，配置里固定选一家 |
| 记忆 | 自己做「话题线加一次决策调用」，见下文；暂时不引入 Hindsight、mem0 这类外部记忆服务 |
| 联网搜索 | 只用服务商内置的搜索工具。两家的展示条款由用户另行确认，见「查证过的外部事实」的「内置搜索」 |
| 处理过程的展示 | 过程一条消息，回答另起一条；过程消息在 2 分钟内可以撤回，撤回可由配置关闭。见「展示处理过程」 |

同一个值只有一个来源：密钥不进配置文件，配置文件里的设置不再从环境变量覆盖。

暂时不用外部记忆服务的理由：调研到的记忆库存的都是提炼出的事实，没有一个会自动给连续对话分段；服务商自带的会话状态只是一条线性历史；Hindsight 的部署对 2G 的机器太重。以后引入的可能性很低，但不排除。

### 已定要做的功能

除上面八项能力外，这些也从一开始就做，细节实现时再定：

1. **邀请带备注**：创建邀请时填一个备注，兑换后成为该用户的名字，管理、用量、日志都用它。机器人看不到 QQ 号，昵称会改也会重名。
2. **管理员的管理面**：列出和停用用户、撤销邀请、查看用量、临时停机。用斜杠命令直接解析，不经过大模型；可以用 pyqbot 的按钮与自定义菜单做成点按。
3. **用量记账**：从第一条消息开始，每次调用记下用户、模型和 token。配额、限流、成本归因都靠它。
4. **遗忘与查看记忆**：「忘掉这件事」「你都记得我什么」做成模型的工具，用户照常说话即可。
5. **欢迎语与拒绝语**：授权成功时说明能做什么、聊天内容会发给第三方模型、提醒功能需要保持「允许主动发送」。未授权的人只回一次固定的拒绝，不调用大模型。
6. **出错时的表现与备用模型**：调用失败或超时时给用户一句明确的话，不沉默；每个类别可以配一个另一家服务商的备用模型。
7. **数据库的迁移与备份**：表结构从第一版就带版本号和迁移机制，并定时备份。
8. **不支持的消息的兜底**：转发的聊天记录、视频、卡片等先明确回一句「暂不支持」。表情包要单独处理，不能每张都触发看图和回复。
9. **「正在输入」**：模型还没开始输出时发，开始流式输出后就不需要了。pyqbot 已有 `send_typing()`。
10. **给管理员的告警**：机器人掉线、额度用尽等，直接发到管理员的 QQ。

### 不做

| 事项 | 态度 |
| --- | --- |
| 群聊 | 明确不做 |
| 自己实现搜索 | 明确不做，只用服务商内置的工具 |
| 主动关怀 | 暂时不做 |
| 到点执行一个请求 | 已定要做，但以后再做；提醒表先留好字段，见「提醒事项」 |

## 接入与授权

pyqbot 已有的能力（实测结论见 pyqbot 的 `docs/errata.md`）：

- `generate_share_link(callback_data=...)` 生成邀请链接，`callback_data` 最长 32 个字符。
- 用户经链接添加后，`FRIEND_ADD` 的 `scene_param` 就是 `callback_data`。这时 `scene` 实测是 1000，不是官方文档写的 2003 / 2004，所以只认 `scene_param`。

链接不是门禁：用户还能通过搜索、群、资料页添加机器人。授权是机器人自己存的一张名单，默认拒绝，对应 `AGENTS.md` 的第一条不变量。

建议，未定：

- `callback_data` 用随机令牌，在本地记录有效期与可用次数，默认一次性。链接可以被转发。
- 留一条兜底通道：同一个令牌能在聊天里发给机器人兑换，或由管理员按 openid 授权。
- 管理员只能用 openid 标识，机器人看不到 QQ 号，需要一个取得它的办法。

## 一轮对话

```text
攒批 → 非文本转文字 → 决策 → 组装上下文 → 模型流式回复 → 后台更新摘要与档案
```

- **攒批**：把短时间内的多条输入合成一次提问。带文字或语音的消息稍等片刻再处理；只有图片或文件的消息多等一会儿，没有后续就直接回应它。同一个用户始终串行。
- **文字版**：每个非文本输入存一份文字版（语音转写、图片描述、文件摘要）。当前这轮，选中的模型支持该模态就给原件，否则给文字版。同一话题最近几轮里的图片和文件原样再带上，更早的只带文字版。
- **决策**：一次 Decisions 调用问两道选择题，见「记忆」。
- **回复**：用 pyqbot 的 `reply_stream()` 流式回复，只有单聊支持，且只能是被动回复。

## 记忆

每个用户存三样东西：

- **消息流水**：所有消息原样追加，是唯一的事实来源。
- **话题线**：自动划分的隐式 session，每条有标题、一段摘要和最近活跃时间。
- **用户档案**：几百字的稳定事实，如称呼、偏好、重要的人和事。

每轮的决策调用问两道题：

- **用哪类模型**：选项是配置里的模型列表，每项带一句类别描述。
- **属于哪条话题线**：选项是候选话题线的标题与一句话摘要，外加「新话题」。

Decisions 返回每个选项的概率，上下文按概率组装：

| 内容 | 何时带上 | 形式 |
| --- | --- | --- |
| 用户档案、话题目录（只有标题） | 每次 | 短文本，让模型知道别的话题存在 |
| 全局最近几轮 | 每次 | 原文，兜住「它」「刚才那个」这类指代 |
| 概率最高的话题线 | 每次 | 摘要加该话题最近若干轮原文 |
| 概率次高、超过阈值的话题线 | 拿不准时 | 只带摘要 |

这样一轮的上下文约 5k–8k token。几个候选模型的窗口都在 100 万 token 上下，限制不在窗口而在费用，所以不把整段历史都带上。

Decisions 只能选、不能写。新话题的标题、话题摘要和档案更新交给后台的小模型，在回复之后做，不占用户等待的时间。

用户引用旧消息时，pyqbot 会在 `msg_elements` 里带回被引用的内容，可以直接定位话题，不必靠猜。

### 留给以后的口子

用户要求留出拓展空间。建议守住三条：

- **流水只追加，其余都是可重建的派生数据。** 话题归属、摘要、档案、文字版都能从流水重新算出来，以后换提示词、阈值或算法时可以对历史重跑。唯一的例外是用户要求遗忘：对应的流水要彻底删除，再重建受影响的摘要和档案。
- **每轮存一条决策记录**：候选、各选项的概率、最终选择、带了哪些上下文、耗时与 token。效果不好时靠它查原因，延迟实测的数据也从这里来。
- **三个接口**：决策、对话模型、语音转写，SDK 隔在接口后面。「生成候选话题」与「在候选里选」分成两步，以后可以给前一步加关键词或向量召回。
- **一次回复是若干段内容，不是一个字符串。** 现在只有文字，以后可以加语音或图片形式的回复。
- **工具不一定在本地执行。** 联网搜索由服务商在它那边执行，工具调用的流程不能假设每个工具都有本地的处理函数。

### 已知的薄弱处

都还没有定做法，实现到相应部分时先和用户确认：

1. **候选话题从哪来**：选择题最多 255 个选项，实际只会列最近几十条，很久以前的话题会被判成「新话题」。
2. **新话题的空窗期**：后台还没写出标题和摘要时，下一条消息认不出这条话题。可以先拿首条消息的原文当临时描述。
3. **决策调用失败或被拦**：超时、安全拦截、拒答都可能发生，情感类内容最容易触发。需要硬超时，并回退到「默认模型加当前话题」。
4. **流水里记什么**：平台可能拒发或流式中途失败，要记用户实际看到的内容，而不是模型生成的内容。
5. **模型来回切换**：两个模型交替回答会像换了个人。各类别共用人设，切换要求概率有明显差距；跨服务商的历史只存纯文本。
6. **连发消息**：攒批的等待可以和决策调用同时进行；期间来了新消息就取消重来，生成过程中来的排到下一轮。
7. **重复推送**：平台可能重复推送同一条消息，pyqbot 不去重，要按消息 ID 去重。

## 展示处理过程

目标是像 ChatGPT 那样：处理时能看到进展，回答出来后过程不碍事。

已定：

- **过程与回答分成两条消息。** 过程用一条流式消息；回答开始时结束它，另起一条流式消息写回答。
- **过程消息在 2 分钟内撤回**，相当于折叠。超过 2 分钟平台不允许撤回，就留着。撤回可以由配置关闭。

QQ 侧的限制（官方文档快照与 pyqbot 的实测）：

- 消息的 Markdown 没有折叠语法，HTML 标签（如 `<details>`）不生效。
- 流式消息的 `replace` 只能接着已下发的内容往后写，不能删改用户已经看到的部分。过程和回答放在同一条流式消息里时，过程去不掉。
- 流式消息的请求体里没有键盘字段，不能带按钮。
- 撤回只在发出 2 分钟内有效，撤回后聊天里会留下一条撤回提示。
- 流式消息每来一片，手机会轻微震动一次。

建议，未定：

- **撤回的时机**：回答开始时，还是回答结束后。
- **过程只写步骤级的短句**（在查什么、发现了什么），放在引用块里，按步骤更新而不是逐字更新。
- **没有过程就不发过程消息。** 模型直接开始回答时只发「正在输入」。
- **按模型类别配置是否展示**，情感陪伴类默认不展示。
- **回答要能独立成立**，不依赖过程里说过的话。过程的全文存进决策记录，不进后续的上下文。
- 回答开始之后再出现的思考或搜索不再展示，只记录。

过程的内容有三个来源，两家服务商给的形式不同，见「查证过的外部事实」的「思考摘要与过程标记」：思考摘要、调用工具前的说明、搜索的查询词。让模型在调用工具前先说明的提示词（如「我先查一下……」）只适合 OpenAI：它用 `phase` 字段把说明和最终回答分开；Gemini 没有这种标记，官方也不建议强制模型在调用工具前输出文字。

## 提醒事项

建议，未定：

- 自己存一张提醒表，加一个「睡到最近一条到期」的 asyncio 任务，启动时补发已过期的。asyncio 自带定时但重启就丢；APScheduler 4 仍是 alpha，3.x 要持久化就得带上 SQLAlchemy。
- 时间解析交给主模型，把「设置提醒」做成工具，对所有模型类别开放；回复里复述解析出的时间，方便用户纠正。
- 到点发出的是主动消息：用户在资料卡关掉「允许主动发送」就会失败，要在用户下次发言时补上。

提醒有两种，区别在于到点时要不要再调用一次模型：

- **到点发一句话**：「8 点提醒我吃药」，到点发出事先定好的内容。第一版做这种。
- **到点执行一个请求**：「明早 8 点告诉我今天的天气」，内容在设定时还不存在，到点要让模型带着工具跑一轮再发出结果。已定要做，但以后再做。它只能作为主动消息发出，不能流式。

提醒表里先留好区分这两种的字段。

## 其它待定

- **配额的具体规则**：每个用户的每日上限、全局预算。工具执行时的用户身份取自当前会话，不取模型给的参数。
- **时间感**：上下文里标注当前时间，以及距上次对话过了多久。
- **数据去留**：用户删除好友后数据保留多久，附件的磁盘清理。
- **情感类的风险处置**：涉及自伤等内容时走固定的模型与回应方式，不交给路由决定。
- **每个模型类别各自的上下文组装方式**：情感陪伴更依赖档案和最近的对话，不像一个个话题。
- **提示词**放在 TOML 里还是独立文件。
- **数据库**设想用 SQLite，访问方式未定。

## 配置的形状

只为说明结构，字段名与数值都没有定：

```toml
timezone = "Asia/Shanghai"

[decisions]
provider = "openai"          # 或 "gemini"
timeout_seconds = 2.0

[decisions.switch_margin]    # 换模型所需的概率差，两家分别配置
openai = 0.2
gemini = 0.3

[process]
recall = true                # 过程消息在 2 分钟内撤回；false 则一直留着

[[models]]
class = "solve"
description = "用户想解决一个具体问题：查资料、写代码、分析、做决定"
provider = "openai"
model = "gpt-6.2-sol"
inputs = ["text", "image"]

[[models]]
class = "support"
description = "用户在倾诉、闲聊或寻求情感支持"
provider = "gemini"
model = "gemini-4-hydrogen"
inputs = ["text", "image", "audio", "file"]
default = true
```

## 需要实测

实测前按 `AGENTS.md` 先取得用户同意。

- Decisions 的实际延迟。两家的官方文档都只有定性说法，没有数字。
- 收到语音、图片、文件时的真实字段，附件地址的有效期，单聊里能不能收到文件。
- 表情包以什么形式到达：文本里的标记，还是图片附件。
- 单聊消息里的昵称字段有没有值。官方示例里是空串，pyqbot 的样本里有值，但可能是脱敏后的占位。
- 单条消息的长度上限，长回复要不要拆条。
- 邀请链接放进消息里能不能发出。
- 已是好友的人点邀请链接、机器人离线时有人添加，这两种情况会不会收到 `FRIEND_ADD`。
- 同一条用户消息能不能先后回两条流式消息。
- 流式消息能不能撤回，2 分钟从哪一片算起。单聊里撤回后会留下一条撤回提示（pyqbot 实测过普通消息）。
- 回答里带任意网站的引用链接时，平台会不会拒发。
- `gpt-6.2-sol` 是否返回思考摘要与 `phase`，账号是否需要先通过组织验证。

## 查证过的外部事实

2026-11-18 查自官方文档，经摘要工具读取，没有实际调用过。这些接口都很新，写代码前以官方文档为准。

### Decisions API

| | OpenAI | Gemini |
| --- | --- | --- |
| 接口 | `POST /v1/decisions` | `POST /v1beta/decisions` |
| SDK | `client.decisions.create()` | `client.decisions.create()`，`google-genai` ≥ 3.2 |
| 模型 | `gpt-6-luna` | `gemini-decision-1` |
| 题型 | `predicate`、`choice`（2–255 项）、`score` | `noul`（是非）、`choice`（2–255 项）、`score` |
| 每次题数 | 1–400 | 1–1000 |
| 输入 | 文本、图片、消息数组；不收音频和文件 | 文本、图片、音频、视频、PDF；历史只能当文本传 |
| 失败形态 | 单道题可能返回拒答 | 安全拦截返回 HTTP 400 |
| 价格 | 每百万输入 token 0.10 美元，不收输出费 | 相同 |
| 状态 | 2026-10-22 正式发布 | 2026-11-11 发布，在 `v1beta` 下 |

两家取交集来用：历史当文本传，语音用文字版参与决策。两家给出的概率不能直接比较，阈值按服务商分别配置。

文档：[OpenAI 指南](https://developers.openai.com/api/docs/guides/decisions)、[OpenAI 接口](https://developers.openai.com/api/reference/resources/decisions/methods/create)、[Gemini 指南](https://aistudio.google.com/docs/decisions-api.md)、[Gemini 模型页](https://aistudio.google.com/docs/models/gemini-decision-1.md)、[Gemini 速率限制](https://aistudio.google.com/docs/rate-limits.md)。

### 内置搜索

| | OpenAI | Gemini |
| --- | --- | --- |
| 接口 | Responses API；GPT-6.2 的工具调用不支持 Chat Completions | Interactions API；`generateContent` 已标为旧接口 |
| 工具 | `{"type": "web_search"}` | `{"type": "google_search"}` |
| 价格 | 每千次调用 10 美元，另计搜索内容的 token | 每月 5000 次免费，之后每千次 14 美元；`gemini-4-hydrogen` 的免费档不可用 |
| 搜索中的事件 | `response.web_search_call.in_progress` / `searching` / `completed`，不含查询词 | `google_search_call` 步骤的 `step.delta` 里带查询词 |
| 查询词在哪 | `web_search_call` 输出项的 `action`，从 `response.output_item.done` 读 | 同上，流式过程中可见 |
| 引用 | 文本里的 `url_citation` 标注 | `model_output` 文本块上的 `url_citation` 标注 |
| 展示要求 | 引用必须显示成醒目的、可点击的链接 | 必须同时展示它给的「搜索建议」，那是一段 HTML |

Gemini 的展示要求在 QQ 里做不到：QQ 渲染不了 HTML。两家的条款由用户另行确认，确认前不要默认在 Gemini 的模型上开启搜索。

文档：[OpenAI 搜索工具](https://developers.openai.com/api/docs/guides/tools-web-search)、[OpenAI 流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events)、[Gemini 搜索](https://aistudio.google.com/docs/google-search)、[Gemini 流式](https://aistudio.google.com/docs/streaming)、[Gemini 条款](https://aistudio.google.com/docs/terms#grounding-with-google-search)。

### 思考摘要与过程标记

| | OpenAI | Gemini |
| --- | --- | --- |
| 开启思考摘要 | `reasoning={"summary": "auto"}`，另有 `concise`、`detailed` | `generation_config={"thinking_summaries": "auto"}`，默认关闭 |

### QQ 平台

出处是 pyqbot 的 `docs/errata.md` 与官方文档快照：

- 单聊被动回复的有效期约 60 分钟，实测 55 分钟后仍能回复。
- 同一条消息实测能先发「正在输入」再被动回复 4 条。
- Markdown 里形如链接、目标却不是 URL 的文字会被判「消息内容违规」（40034006），大模型的输出要先处理。
- 语音附件带 `voice_wav_url`（转成 WAV 后的地址）与 `asr_refer_text`（识别的参考文本）。pyqbot 已有这两个字段，没有实测过。
- 单聊主动消息的官方限额是每个用户每天 1000 条。用户切换资料卡里的开关时，平台推的是 `type` 18 的互动事件。
